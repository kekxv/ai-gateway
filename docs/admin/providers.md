# 供应商管理

## 上游余额查询

供应商可查询上游账户余额，用于在上游额度耗尽前发现问题。余额查询在供应商级别配置，支持三种方式确定上游类型：

- **手动选择**：在编辑面板的“上游余额查询”中直接选择上游类型。
- **自动检测**：点击“自动检测接口”，网关会依次探测 new-api / one-api、DeepSeek、OpenRouter 的余额接口。只命中一个时自动选中并立即记录余额；命中多个时列出候选及其余额，由管理员确认后保存；全部失败时返回 `502 balance_detection_failed`。自动检测只在内置类型中探测，不会猜测“自定义接口”的字段映射。
- **自定义接口**：适用于其它上游，需要填写请求路径与余额字段路径，可选已用额度、可用状态字段路径、请求方法和额外请求头。

内置类型及其默认行为：

| 类型 | 请求 | 说明 |
| --- | --- | --- |
| new-api / one-api | `GET {host}/api/user/self` | 读取 `data.quota` 与 `data.used_quota`，默认按 500000 额度 = 1 美元换算（上游改过 QuotaPerUnit 时填“余额除数”）；**只接受用户访问令牌**，见下方说明 |
| DeepSeek 官方 | `GET {host}/user/balance` | 读取 `balance_infos` 与 `is_available`，可用“币种”选择列表中的某一币种，默认取第一条 |
| OpenRouter | `GET {base}/api/v1/credits` | 余额 = `total_credits - total_usage` |
| 自定义接口 | 管理员配置 | 字段路径使用点号访问嵌套字段，用 `[序号]` 访问数组元素，例如 `data.balance_infos[0].total_balance`；可用“余额除数”换算额度单位 |

基础地址默认使用该供应商首选协议的 `base_url`（new-api 与 DeepSeek 会自动去掉 `/v1`、`/v1beta` 后缀），也可以单独填写“余额查询基础地址”。查询默认复用供应商凭据；需要单独凭据时填写“覆盖查询密钥”，它与自定义请求头一起加密存储，管理接口只返回是否已配置。

编辑面板中的空值语义分成两类：

- **查询密钥与请求头**：留空表示保持已保存的值（密钥不会回填到表单）。要删除已保存的值，勾选字段下方的“保存后清除……”。
- **其它字段**（基础地址、用户 ID、币种、余额除数、自定义接口的路径与字段路径）：留空表示提交 `null`，即删除该覆盖项并恢复默认值——基础地址回到供应商协议地址，user_id 不再发送 `New-Api-User` 请求头，币种回到 `USD`，余额除数回到该类型默认值（new-api 为 500000，其它为 1）。

余额有三种触发方式：

- **单个查询**：在供应商卡片上点击“查余额”。
- **定时同步**：在编辑面板打开“自动同步余额”并设置“余额同步间隔（秒）”，后台调度按每个供应商自己的间隔执行，并在多个实例之间使用数据库锁避免重复查询。
- **批量查询**：页面右上角的“批量查询余额”按钮会依次查询所有已配置余额查询的供应商，并在弹窗表格中逐行展示上游类型、成功/失败、余额、已用、同步时间与失败原因；未配置余额查询的供应商只计入“未配置”数量而不参与查询，已停用的供应商仍会查询并在表格中标记“已停用”。结果与单次查询一样写入余额快照，因此关闭弹窗后供应商卡片上的余额就是最新值。

查询失败时保留上一次成功读取的余额，并把错误信息记录在供应商卡片的“余额查询失败”提示中，同时更新最后同步时间。

切换上游类型会清空旧的余额快照（金额、币种、更新时间），把类型改为“不查询余额”还会一并清空余额配置。余额查询使用与模型同步相同的出站代理配置。对应的管理接口为 `POST /admin/providers/{id}/balance/sync`、`POST /admin/providers/{id}/balance/detect`，批量查询为 `POST /admin/providers/balance/sync`（返回 `results` 行以及 `synced` / `failed` / `skipped` 计数，单个供应商失败不影响其余结果）。

### new-api / one-api 返回 `401 AUTH_UNAUTHORIZED`

`/api/user/self` 属于 new-api 的管理接口，只接受在**上游控制台「个人设置」生成的访问令牌**（Access Token）；`sk-` 开头的中转密钥只在 `/v1/*` 上有效，因此默认“复用供应商凭据”的余额查询会对这类供应商返回：

```json
{"code":"AUTH_UNAUTHORIZED","message":"Unauthorized, invalid access token","success":false}
```

修复方式：在供应商编辑面板的“覆盖查询密钥”中填写该访问令牌（留空表示继续复用供应商凭据）。“new-api 用户 ID”（`New-Api-User` 请求头）只在部分部署中强制校验，多数版本不填也能查询成功；若上游返回用户不匹配的错误再补充填写。

可以先在服务器上用 curl 直接确认令牌类型是否正确（把 `$BASE` 换成上游域名，**不要带 `/v1`**）：

```bash
curl -sS "$BASE/api/user/self" -H "Authorization: Bearer $ACCESS_TOKEN" -H "New-Api-User: $USER_ID"
```

成功时返回 `data.quota`（剩余额度）与 `data.used_quota`（已用额度）；用中转密钥请求同一地址会得到上面那个 401。自动检测同样复用这套凭据，因此在填好访问令牌之前，“自动检测接口”无法识别 new-api 上游；检测全部失败时接口会在 502 消息里列出每个候选接口各自的失败原因。


## 同步上游倍率与模型价格

new-api / one-api 会在 `GET {上游根地址}/api/pricing` 公开自己的倍率表：每个模型带 `model_ratio`（模型倍率）、`completion_ratio`（补全倍率），顶层带 `group_ratio`（分组倍率），按次计费的模型只给 `model_price`。供应商卡片上的「同步价格」会读取这份数据，把它换算成本地模型价格；**价格与倍率是两件事**：价格写进模型，倍率只在你选定分组后写进供应商「成本倍率」。

### 换算规则

- 上游倍率单位：1 倍率 = 2 美元 / 百万 token，因此 `输入价格 = model_ratio × 2`、`输出价格 = 输入价格 × completion_ratio`（例如 `model_ratio 1.25` → 2.5 / 10）。
- 写入的是**上游标价**，不含分组折扣；对外的用户价格仍由「公开倍率」决定。
- 按次计费（`quota_type = 1`）的模型无法换算成每 token 价格，会在结果里标记为「按次计费」并跳过。
- 缓存读写价格不参与同步；需要计费时在模型编辑面板里手动填写。

### 只补空价格

模型价格一旦设置过（四个价格字段任一非 0），同步就不会覆盖它，结果里显示为「已设置」并同时给出上游价格与本地价格以便对照；这类模型只能手动改价。判定口径是「四个价格字段全为 0 即视为未设置」，所以把价格改回 0 就等于允许下次同步重新补齐。

### 成本倍率只按你选择的分组写入

对话框里的「成本倍率分组」列出上游 `group_ratio` 中的全部分组及其倍率（例如 `svip · 0.25x`、`default · 2.5x`），默认是「不更新成本倍率」：**只有你明确选定分组，才会用该分组的倍率覆写供应商「成本倍率」**，并写入审计日志。命中该供应商的请求按 `基础价格 × 模型倍率 × 成本倍率` 计算平台成本，所以 0.25x 的分组倍率意味着平台成本打到 2.5 折。

系统不会替你猜分组：`GET /api/user/self` 返回的是**账号（用户）分组**，而 new-api 计费时用的是**令牌分组**（`token.Group` 非空即覆盖账号分组），两者可能不同。因此弹窗只把账号分组显示成一行参考提示，既不会预选也不会自动写入——上游账号在 `default`（2.5x）、令牌在 `svip`（0.25x）时，自动写入会把成本倍率错写成 2.5。

### 触发方式

- **手动**：供应商卡片上的「同步价格」，弹窗分两步——先读取上游并列出分组与可补齐数量，点「开始同步」后才真正写库，随后展示明细表（已更新 / 已设置 / 按次计费 / 未列出 四个计数、成本倍率变化与逐模型对照）。
- **跟随模型同步**：手动「同步」和定时模型同步都会在上游支持价格表时顺带补齐空价格，并在同步通知里报告「补齐模型价格 N 个」；这条路径**只补价格，绝不修改成本倍率**，也不会请求 `/api/user/self`。上游没有 `/api/pricing`（例如官方 OpenAI、Anthropic 直连）时静默跳过，不影响模型同步本身。

管理接口：`GET /admin/providers/{provider_id}/upstream-pricing` 只读取并预览（返回 `group_ratios`、`detected_group` 与各状态计数，不写库）；`POST /admin/providers/{provider_id}/sync-model-prices` 执行同步，请求体可选 `{"group": "svip"}`。上游不可用或没有价格表时返回 502 `model_price_sync_failed` 并带上游报错，选择的分组不在上游倍率表里时返回 422 `invalid_price_group`。

## HTTP(S) 出站代理

每个供应商可以独立选择出站网络路径，普通请求、流式请求和模型同步使用同一配置：

- **继承全局配置**：使用 `GATEWAY_HTTP_PROXY`、`GATEWAY_HTTPS_PROXY` 和 `GATEWAY_NO_PROXY`，也是历史供应商的默认行为。
- **强制直连**：忽略全局代理，直接连接该供应商。
- **供应商专用代理**：使用指定的 `http://` 或 `https://` 代理，并覆盖全局代理和 `NO_PROXY`。

专用代理支持无鉴权、帐号密码（HTTP Basic）和自定义代理请求头。代理 URL 不允许包含帐号密码、路径、查询参数或片段；帐号密码和自定义请求头需要在独立鉴权字段中填写，整份代理配置会加密存储，管理接口只返回地址、鉴权类型和是否已配置鉴权。

帐号密码代理同时支持 HTTP 请求、模型同步和 WebSocket CONNECT。WebSocket 代理的 Basic 帐号密码必须为 ASCII；帐号不能包含 `:`、`/`、`?`、`#`、`[`、`]`，密码不能包含 `/`、`?`、`#`、`[`、`]`。当前 WebSocket 客户端没有添加任意 CONNECT 请求头的公共接口，因此自定义代理鉴权请求头不能与供应商的 `websocket_url` 同时配置。不兼容的配置会由管理接口返回 `422 invalid_provider_proxy`；仅用于 HTTP 的供应商不受这些 WebSocket 限制。

编辑已鉴权代理时不会回填帐号、密码或请求头；保持地址和鉴权类型不变并将敏感字段留空会保留原配置。修改代理地址或鉴权方式时必须重新输入完整鉴权信息。目录导出默认省略代理详情，只有显式选择包含机密信息时才导出完整配置；导入包未提供 `proxy` 时保留已有配置。

## 价格倍率配置

价格倍率用于调整最终计费价格，支持在供应商级别配置。

### 计算公式

最终价格 = 基础价格 × 模型倍率 × 供应商倍率

### 配置说明

- **范围**: 0.10 ~ 10.00
- **默认值**: 1.00（无倍率效果）
- **精度**: 2 位小数

### 使用场景

供应商倍率适用于特定供应商的整体价格调整：
- 例如: 某供应商提供折扣，设置 0.80 表示 8 折
- 例如: 某供应商成本较高，设置 1.20 表示加价 20%

### 注意事项

1. 供应商倍率与模型倍率相乘应用
2. 倍率修改会立即生效
3. 倍率变更会记录到审计日志
4. 「同步价格」只在你于弹窗中选定分组时才覆写成本倍率（写入审计日志）；不选分组就完全不动，跟随模型同步的自动路径也不会修改它
